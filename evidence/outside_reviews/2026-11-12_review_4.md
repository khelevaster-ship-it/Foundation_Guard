Note on the AI tool's own box: with the kit's recommended list applied, Claude Code's own (unlabelled) box still asks

## 1. Verdict

No. In one ordinary-looking shell line, a helper can switch the whole guard off with no box from the kit
(`echo '{"parts":{"guard":"off"}}' > "$CLAUDE_PROJECT_DIR/foundationguard.json"`). In two lines it can give the owner's
yes itself, and in two commands that the recommended list lets through with no box at all (`git fetch` and the kit's
own push) it can upload a weakened test to GitHub while the asks are gathered. The ideas are sound and the
plain-words design is good, but today the guarantees in C1, C2, C3, C5 and C7 hold only against a helper that never
tries a second spelling, and the honest-but-stubborn helper has easier ways round than "write a script".

## 5. False alarms

New since the fixes:
- **F223 blocks a one-liner that only *prints* git words after running something else.** `python3 -c "import subprocess as s; out=s.run(['git','status','--porcelain'],capture_output=True,text=True).stdout; print('clean' if not out else 'commit first, then git push')"` → BLOCK "push directly is not allowed". Same for `node -e "...execSync('npm test'...); console.log('next: git push via fg/push.py')"` and `python3 -c "import os; os.system('pytest -q'); print('If this fails do NOT run git reset --hard')"`. Rare, but the block message names a command the line never runs, which will confuse a helper.
- F222 and F224: none found. Twelve ordinary new tests (monkeypatch, local objects, parametrize, `tmp_path`, Godot `World.new()`, C++ lambdas, out-parameters, a spawned Unreal actor) all went through with no ask.

Older, still there:
- A new Unreal **Automation Spec** file (`BEGIN_DEFINE_SPEC` ... `It("...", [this]() {...})`) asks: "the new file holds no test". Spec is a standard Unreal test style, so every new spec file asks the owner.
- `git restore FILE` and `git checkout -- FILE` block (by design; the block names `git stash`, which is right).

What would make an owner give up: the unlabelled boxes from the AI tool's own list (every `echo >`, `git apply` and the like asks there), which look like the kit's and wait all night; and the Spec ask on an Unreal project.

## 6. The owner's questions

**1. Overnight.** The worst case is everything. With one line from finding 1 (or one `git apply`), the guard is off for the rest of the session, and nothing after it is logged, because a switched-off guard writes nothing. Then: `git reset --hard`, `git clean -fdx`, deleting `.git`; overwriting other people's remote branches (finding 5); uploading untested commits (finding 6); a yes "from the owner" in the catch log (finding 3). Yes, it reaches GitHub on any branch without GitHub's protection. And with no unusual command at all, `git fetch` plus the kit's own push uploads a gathered weakening (finding 4), with no box from the kit or the recommended list. The owner would notice only by reading the git history; the morning summary would say nothing waits for a yes.

**2. The honest but stubborn helper.** Easier than a script: write the file with an absolute path in the kit's own style, `cat > "$CLAUDE_PROJECT_DIR/tests/test_a.py" <<'EOF'`, after an Edit asked. Helpers often switch to absolute paths after a tool error, and this one gets no kit box. Next easiest: `git apply` of a patch, and on Windows `[IO.File]::WriteAllText(...)`, a usual way to write UTF-8 without a BOM in PowerShell. For a stopped upload: `git fetch` to "refresh" and then `python fg/push.py` again, which a helper might well try, and which uploads.

**3. Weakened tests called "only adds tests".** Python: `def __init__(self)` added to a test class (finding 9; tested end to end: broken game uploaded). GDScript: `func should_skip_script(): return "slow"` (FREE; GUT behaviour READ). C++: `GTEST_FLAG_SET(filter, "-G.A");` inside a new test is FREE, but gtest reads the filter before the tests run, so I don't count it. Shared state in new tests: section 2, F224.

**4. Checks that don't bite.** Each feature broken another way; its own check still passed (`pytest -k "runs_too_long or shared_value_in_place or more_art_types"`: 3 passed):
- **F227:** limit raised to 90 s and the clamp to 120 s (guard.py 68, 80): passes; the test sets 2 s itself and only waits on input.
- **F224:** `erase`, `merge`, `push_back`, `pop_back`, `remove_at`, `resize`, `fill` taken out of the list (adds.py 70): passes, and `GlobalState.items.erase('a')` then goes FREE.
- **F226:** `bank`, `bnk`, `wem`, `fsb`, `sf2` taken out (assets.py 38): passes; only `.ktx2`, `.mid`, `.ply`, `.bk2` and the extra type are tested.
- Also **F217:** its check doesn't cover a moved `origin/BR` (finding 4).

**5. False alarms.** Section 5.

**6. Plain words.**
- README "A helper cannot give it" and GUIDE "A helper cannot give that yes" are not true (finding 3).
- The stated limit "A helper is asked before it writes one [record]" is not true (findings 1, 2).
- The session line "Risky commands are blocked, and changes to tests and guard files ask the owner" reads as a promise. "Blocks the usual spellings of risky commands" would be honest.
- The weakening finder calls it "not weaker" (so the box says "this change doesn't look weaker") when a change points a row's break at a switch nothing reads (`env:SAVE_COMPAT=0` → `env:UNUSED=1`). Break-to-prove would catch it at the next proof, but the owner is told it's fine at the moment of the yes.
- The report "Nothing needs your attention" after finding 4's upload is the most dangerous sentence in the kit, because it is the one the owner reads in the morning.

**7. Release.** Must change before outside users: findings 1 to 6 (each is one or two lines to get round a central promise), finding 8, and the wording above. Then say plainly in the README that, on its own machine, the kit is a speed bump against a helper that tries a second spelling, and that GitHub branch protection with a required check is needed on **every** branch that matters, not only main. Fine as it is: the plain-words cards and labels, the break-to-prove idea and the approved list, fail-closed on a crash (I couldn't make it crash open), the copy-in-as-text rules for tests, the gate itself (it caught a real broken commit in my run), and the no-dependency, standard-library design.
