B. A missing record makes the after-step check skip, then accept (medium). With .git/foundationguard/steps/state.json gone, steps.py --after crashes ("too many values to unpack"), prints "guard files were not compared this time", and takes the files as they are as the new accepted state. Cause: _check() returns four values on that path and after() expects three. More broadly, any crash in the after-step check lets the step stand, while the guard before the step blocks on a crash. Fix the return, and add a test that removes the record between the two hooks.

The kit's block messages for git checkout -- and git restore say "use git stash".
A stash that includes tests, even brand-new uncommitted ones (which are otherwise free), gets them put back into the folder.
